# План развития (P0–P7 по ТЗ-05 §12)

Текущая редакция **1.2.0**. Замечания ведомости корректирующих изменений v1.1
(ИД-01…ИД-12) устранены и закрыты контрольными испытаниями; дополнительно
выполнены очередные пункты P4 и P6. Ниже — что сделано и что требуется для
промышленной эксплуатации.

Сводное состояние проверок: **112/112** модульных тестов, **69/69** проверок API
для каждой из 6 ролей (82/82 в режиме `--run`), **61/61** проверок интерфейса.
Единый файл запуска: `release/ISHEIKA-NTR-AI.exe` (сборка `tools/build_exe.py`).

## P0. Каркас и реестры — ✅ готово

* Схема данных (53 таблицы + представления), контракты, 7 конечных автоматов,
  профили DEV/PILOT/PROD, миграции `0002_tz_v11` и `0003_observability`.
* Реестры: 806 источников, 35 стран, 24 коннектора, 18 провайдеров, 11 моделей,
  12 агентов, стоп-лист, «кладбище API».
* **Реестр методик (ИД-09)**: `RELEVANCE_V1`, `FEASIBILITY_V1`, `TRL_CRITERIA_V1`,
  `FORECAST_V1`, `SOURCE_QUALITY_V1`, `EVIDENCE_QUALITY_V1` — формулы, параметры,
  пороги, сроки действия, статус утверждения, контрольные суммы, контрольные
  примеры; новая версия не перезаписывает прежнюю (UI-27).
* Инструмент парсинга перечня (`tools/parse_registry.py`) — повторное наполнение без правки кода.

## P3. Расчётное ядро и отчёты — ✅ готово

* TRL (цепочка обязательных критериев, усреднение запрещено), реализуемость
  `F = 100·Σw·x·a/Σw·a` с покрытием `C`, барьеры, альтернативы, тренды, прогноз
  0–50 лет с **серверной политикой представления** (ИД-05), паспорт, качество.
* **Разделение показателей (ИД-10)**: F (0–100), P(T≤t) (0–1) и уверенность (0–1) —
  три независимые записи; P не выводится из F.
* **Независимость доказательств (ИД-11)**: `origin_class` + `independence_group_id`;
  перепечатки одного сообщения не увеличивают число независимых подтверждений (UI-28).
* **Воспроизводимость (ИД-12)**: снимок входов, версии методик/моделей/промптов,
  контрольные суммы, повторный расчёт по снимку (`POST /api/v1/replay`, UI-29).
* Отчёты HTML/PDF/DOCX/XLSX/JSON/CSV; раздел «Методика и версии» печатает версии
  **из реестра, связанные с результатом**, а не текущие активные.
* **Далее:** калибровка на пилотной выборке (разметка ≥ 30 документов, эталонные пары
  TRL, ретроспективные прогнозы), утверждение весов и порога покрытия `C = 0,60`
  (сейчас `PROVISIONAL`), перевод методик в статус `VALIDATED`.

## P5. Промышленный контур — ⛔ не начато

1. **СУБД:** PostgreSQL вместо SQLite. Схема совместима по составу полей; заменить
   `storage/db.py` (единая точка доступа), перевести JSON-поля в `jsonb`, добавить
   индексы и партиционирование `content_documents` по исследованиям.
2. **Поиск:** OpenSearch или PG FTS + pgvector. Заменить бэкенд в `search/manager.py`,
   сохранив контракты `Document`/`RelevanceResult`; включить эмбеддинги в компоненту S.
3. **Очередь:** Redis + воркеры вместо потоков. Интерфейс `start/status/cancel/resume`
   и идемпотентные ключи сохраняются; добавить распределённые блокировки.
4. **Транспорт:** `uvicorn isheika.api.adapters_fastapi:app` (адаптер готов),
   Pydantic-схемы поверх существующих контрактов; OpenAPI 3.1 уже публикуется
   (`GET /api/v1/openapi.json`, 72 пути).
5. **Граница:** TLS, OIDC/SSO, rate limiting, WAF, ротация секретов (KMS/Vault вместо
   локального файла), резервное копирование и PITR.

## P6. Наблюдаемость и эксплуатация — 🟡 частично

* Есть: события, аудит, история состояний, счётчики квот, здоровье коннекторов и
  провайдеров, экспорт журнала (TXT/JSON/CSV), проверки целостности.
* **Новое в 1.2.0:**
  * сквозная трассировка `request_id` / `correlation_id` (`isheika/telemetry.py`):
    HTTP-запрос → задание → этап → вызов внешнего API → расчёт; заголовки
    `X-Request-ID` / `X-Correlation-ID` принимаются и пробрасываются обратно,
    внешние значения проходят строгую проверку формата;
  * `GET /api/v1/trace/{correlation_id}` и экран трассировки в UI-24 (переход по
    идентификатору из таблицы событий);
  * метрики Prometheus: латентность этапов (средняя/максимальная), доля `partial`
    по этапам и исследованиям, доля размеченных трассировкой событий, средняя
    длительность вызовов внешних API по источникам.
* **Далее:** трейсинг OpenTelemetry (экспорт спанов), алерты и дашборд SLO
  (доступность ≥ 98 %/мес), нагрузочные испытания на 100k–1M+ документов,
  регламент восстановления.

## Единый файл запуска — ✅ готово (задача 2)

`tools/build_exe.py` собирает `release/ISHEIKA-NTR-AI.exe`: SFX-заголовок 7zSD.sfx +
конфигурационный блок + 7z-архив со встроенным CPython 3.11 (x64) и приложением.
Установка Python на целевой машине не требуется; данные хранятся в
`%LOCALAPPDATA%\IsheikaNTR-AI`. Проверки сборки: структура PE/архива, запуск образа
под wine64 (`--verify-wine`) и прогон приёмочных тестов внутри образа
(`--verify-tests`).

**Далее:** цифровая подпись файла (Authenticode), установщик с ярлыками и
автозапуском, вариант со встроенным PostgreSQL для PILOT.

## Приёмка промышленной версии

Численные критерии (Precision@10 ≥ 0,70; nDCG@10 ≥ 0,75; TRL MAE ≤ 1; Brier ≤ 0,20;
покрытие 90 % интервалов 85–95 %) подтверждаются **программой и методикой испытаний**
на пилотной выборке. До этого во всех экранах и отчётах выводится статус
«калибровка не завершена» — это требование ТЗ-03 §8, а не дефект.
