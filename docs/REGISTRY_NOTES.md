### Расхождение по числу стран: 33 / 35 / 36

В разных разделах комплекта встречается 33, 35 и 36 государств. **Принято 35** — как в
основном ТЗ-01 (§требования к охвату) и в ТЗ-04 (профили стран). Реестр `dict_countries`
содержит ровно 35 записей; международные источники не привязаны к стране.
Изменение состава стран выполняется через UI-22 без правки кода.

### UNKNOWN ≠ «открытый»

Около 660 позиций перечня не содержат явного указания на условия доступа. Они получают
`access_class = UNKNOWN` и `integration_status = CANDIDATE` и **не включаются в продуктивный
поиск** до проверки. Это требование ТЗ-01: неизвестное не считается разрешённым.

## 2. Политика robots.txt и документированные API

Глобально `respect_robots = true`. Обнаружены два источника, у которых `robots.txt` запрещает
автоматический доступ к путям, где расположен **официально документированный API**:

| Источник | robots.txt | Решение |
|---|---|---|
| arXiv (`export.arxiv.org`) | `User-agent: * / Disallow: /` | `robots_policy = api_terms`: доступ к документированному эндпоинту `export.arxiv.org/api/query` регулируется условиями API (1 запрос / 3 с), а не правилами для веб-краулера |
| Zenodo (`zenodo.org`) | запрещает `/api`, разрешает `/api/records/*/files`, `Crawl-delay: 10` | то же: REST API документирован и имеет собственные условия и квоты |

Обоснование: robots.txt — механизм для веб-краулеров; для программного интерфейса действует
отдельный договор условий (`api_terms_url` в карточке коннектора). Политика применяется
**точечно к конкретному коннектору и только к его документированному эндпоинту**, каждое
обращение журналируется. Прочие пути этих доменов остаются под запретом. Глобальное
отключение robots не предусмотрено и не используется.

Для всех остальных коннекторов `robots_policy = strict` (по умолчанию).

## 3. Фактические особенности API (исправлено в коннекторах)

| API | Наблюдение | Реализация |
|---|---|---|
| **Crossref** `/works` | не поддерживает `select=language`; фильтры `from-pub-date`/`until-pub-date` требуют полной даты | список `select` без `language`; даты нормализуются до `YYYY-MM-DD`; polite pool через `mailto=` |
| **OpenAIRE Graph** | «Too many logical operators found. Max allowed is 4» | выражение дробится на подзапросы (≤ 4 терма) по ветвям и языкам |
| **OSTI** `/api/v1/records` | при urlencoded-запросе отдаёт JSON-массив, а не XML | формат определяется по первому символу тела, парсятся оба варианта |
| **ROR** | актуальна версия **v2** | используется `api.ror.org/v2/organizations` |
| **NASA NTRS** | **HTTP 403 без ключа** (вопреки описанию в перечне) | статус `RESTRICTED`/`error`, честная фиксация причины; подключение после внесения ключа |
| **Semantic Scholar (S2AG)** | **HTTP 429 без ключа** | статус `rate_limited`, Retry-After/backoff, fallback на альтернативный источник |
| **OpenAlex** | без ключа — общий дневной бюджет, первая страница; с ключом — курсор | лимиты берутся из карточки, курсор включается только при наличии ключа |
| **CORE v3** | скачивание PDF в обход API ведёт к блокировке ключа | стоп-лист STOP-04 блокирует `fileserver-az.core.ac.uk` |
| **EPO OPS** | OAuth2, 4 ГБ/нед, окно 19:00–07:00 GMT | квоты и окно — в `quota_policy`, не в коде |
| **USPTO ODP / KIPRIS** | требуют `X-API-KEY` / регистрацию (1000/мес) | `requires_key = true`, статус `RESTRICTED` до внесения ключа |

## 6. Очереди и приоритеты

P1 OpenAlex/Crossref/Unpaywall/CORE/arXiv/DOAJ → P2 EPO/USPTO/Роспатент → P3 NTRS/OSTI/HAL →
P4 NSF/NIH/UKRI/KAKEN/CORDIS → P5 ETSI/ITU/IETF/ISO/ГОСТ → P6 GDELT/RSS/StackExchange/GitHub →
P7 национальные OAI-PMH через data-providers CORE.

Контроль покрытия **К2**: для каждой страны фиксируется «найдено / класс П / дата успеха»;
страны с нулём попадают в «Карту пробелов» (UI-22, отчёт §8) — это ограничение охвата,
а не отсутствие научно-технической деятельности.

## 7. Офлайн-снапшоты и архивирование

Для устойчивости к недоступности API предусмотрены официальные дампы: OpenAlex S3, Crossref
public data file, DOAJ dump, PMC OA, arXiv S3, USPTO bulk, Wikidata dumps. Веб-архив —
`archive.org/wayback/available?url=` (только для страниц, разрешённых к автоматическому доступу).
Поле `evidence_items.archive_url` сохраняет ссылку на архивную копию доказательства.
