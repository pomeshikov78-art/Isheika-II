# Архитектура ИЩЕЙКА НТР AI

Соответствие архитектуре ТЗ (L1–L7) и ТЗ-05 (компоненты C01–C40). Предметное ядро не зависит
от транспорта, СУБД и способа доставки ИИ: все три заменяемы адаптерами.

## 1. Слои

| Слой | Назначение | Файлы |
|---|---|---|
| **L1** Представление | SPA UI-01…UI-26, SVG-инфографика, состояния экранов | `isheika/web/*` |
| **L2** API-транспорт | REST `/api/v1/*`, SSE, выдача файлов; RBAC-проверки на входе | `api/server.py`, `api/adapters_fastapi.py` |
| **L3** Сервисный слой | валидация, идемпотентность, аудит, права | `api/service.py` |
| **L4** Оркестрация | 12 этапов ИВП, задания, события, отмена/продолжение | `workflow/{engine,pipeline,events}.py` |
| **L5** Домен | поиск, ИИ-агенты, расчётное ядро, доказательства, отчёты | `search/*`, `ai/*`, `analytics/*`, `reports/*` |
| **L6** Интеграции | коннекторы источников, адаптеры провайдеров ИИ, квоты, robots | `search/connectors/*`, `ai/adapters.py`, `search/{http,quota}.py` |
| **L7** Данные | схема, реестры, секреты, кэш, файлы отчётов | `storage/*`, `registry/*`, `var/*` |

Правило зависимостей: L1 → L2 → L3 → L4 → L5 → L6 → L7. Обратных вызовов нет;
домен уведомляет верхние слои только событиями (`workflow/events.py`).

## 3. Информационно-вычислительный процесс (12 этапов)

```
task_setup → search_model → source_search → document_processing → relevance_filter
→ ai_tasks → collective_analysis → evidence_base → math_core → forecast
→ quality_control → report
```

Каждый этап — запись `workflow_jobs` с полями `status`, `attempts`, `progress`, `processed`,
`total`, `idempotency_key` (`<rid>:<stage>:v1`), `depends_on`, `error_code`.
Свойства:

* **Идемпотентность.** Повторный `create_workflow` не создаёт дубликаты; повторный запуск
  завершённого этапа не пересчитывает его (проверяется автотестом).
* **Восстановление.** `start(resume=True)` переводит в очередь только `failed/partial/retry_wait`.
* **Частичный результат.** Если часть источников недоступна, этап `source_search` получает
  `partial`, исследование продолжается и помечается `partial` — данные не теряются.
* **Отмена.** Кооперативный флаг между этапами; состояние фиксируется в истории.
* **События.** 30 типов (`job.*`, `search.*`, `document.*`, `ai.*`, `analytics.*`, `forecast.ready`,
  `report.ready`, `system.*`) пишутся в `workflow_events` и рассылаются подписчикам SSE;
  клиент может дозапросить историю с момента последнего события.

## 4. Поисковый контур

1. `query_parser` — сущности, назначение, период, типы документов, ограничения, исключения.
2. `expansion` — синонимы RU, переводы EN, аббревиатуры, ветви запроса (ядро RU / core EN /
   аббревиатуры / прикладные), версия расширения.
3. `manager.select_connectors` — отбор по категориям C01–C12, классу доступа (A0…A4),
   наличию ключа, политике free-first; имитационный коннектор только в DEV.
4. `connectors/*` — 24 адаптера: официальные API (OpenAlex, Crossref, arXiv, DOAJ, Europe PMC,
   DataCite, OpenAIRE, OSTI, HAL, ROR, Zenodo, StackExchange, GitHub, Unpaywall, CORE,
   EPO OPS, USPTO ODP, KIPRIS, NTRS, S2AG…). Каждый описывает `capabilities`, `limits`,
   `quota_policy`, `robots_policy`, `fallback_code`.
5. `http` — единая точка выхода: User-Agent с контактом, таймауты, кэш, стоп-лист, SSRF,
   robots, Retry-After, журнал `audit_api_calls`, счётчики квот.
6. `normalize` — нормализация метаданных, DOI/идентификаторы, content-hash + simhash,
   дедупликация с сохранением связи `duplicate_of`, класс доказательства и группа независимости.
7. `relevance` — компоненты S/T/C/E/K/F, взвешенная сумма, классы direct/adjacent/excluded,
   поле `S_method` (честно указывает, что эмбеддинги не подключены).

## 5. Контур ИИ

* **Реестр**: `ai_providers` (18), `ai_models` (11), `ai_agents` (12, A01–A12) — данные, не код.
* **Маршрутизация**: `Q(m,t)` учитывает бесплатность, подтверждённое качество, язык, JSON-режим,
  контекст, доступность. Порядок групп: `free → free_alt → local → paid(только с разрешения)`.
* **Контракт**: запрос и ответ полностью соответствуют ТЗ-02 §3; `prompt_version`/`prompt_hash`
  обеспечивают воспроизводимость; `usage`, `latency_ms`, `estimated_cost` — из ответа провайдера.
* **Надёжность**: валидация JSON Schema → одна попытка исправления → `schema_error` →
  fallback на следующего кандидата с новым `request_id` при том же `task_id`.
* **Коллективный анализ**: независимые оценки → перекрёстная проверка → арбитраж → синтез;
  конфликты фиксируются явно (`ai_consensus.conflicts`), итог опирается на Evidence.
* **Безопасность**: `ai/safety.py` — класс приватности, запрет отправки секретов,
  нейтрализация инструкций из документов (prompt injection), политика `policy_blocked`.
* **DEV-режим**: `ai/simulation.py` — детерминированный экстрактор сигналов; ответы помечены
  `simulated=1` и не выдаются за мнения моделей.

## 6. Расчётное ядро

Не зависит от ИИ: если агент недоступен, сигналы извлекаются детерминированно, а результат
помечается источником (`producer`). Каждый расчёт сохраняет `methodology_version` и
`input_hash` — результат воспроизводим и сравним между запусками.

* **TRL** — обход уровней 1→9, обязательные критерии, минимум доказательств и независимых групп
  на уровень; пробелы (`gaps`) фиксируются с причиной; усреднение запрещено.
* **Реализуемость** — веса 15/15/15/15/10/10/10/5/5 %, неизвестные факторы исключаются
  из знаменателя, покрытие `C` снижается, диапазон расширяется при неполном покрытии;
  чувствительность: исключение фактора и вес +30 %.
* **Барьеры** — 11 классов, критичность/вероятность как стартовые эвристики с явной пометкой.
* **Прогноз** — логистическая экстраполяция + качественные сценарии; монотонность `P(T≤t)`
  проверяется и сохраняется флагом; на 20–50 годах числа не публикуются.
* **Качество** — метрики на размеченной выборке, проверки целостности (FACT без Evidence,
  Evidence без Claim, монотонность прогноза, хеши), статус калибровки.

## 7. Данные

53 таблицы SQLite по ТЗ-06 (+ представление `research_documents`): `core_*` (пользователи,
исследования, проекты, история состояний, секреты), `registry_*` (источники, коннекторы,
страны, стоп-лист, changelog), `search_*`, `content_blobs`/`content_documents`/
`content_occurrences`/`content_clusters`/`content_cluster_members`/`content_relations` (ИД-03),
`knowledge_*`, `evidence_items` + `evidence_independence_groups` (ИД-11), `ai_*`, `analytics_*`
(включая `analytics_methodologies`, `analytics_trl_criteria`, `analytics_confidence`),
`forecast_runs` + `forecast_points` (ИД-05), `research_runs` (ИД-12), `reporting_reports`,
`audit_*`, `workflow_*`.

Миграции: `0002_tz_v11` (переход 1.0 → 1.1 с сохранением исходных таблиц как `*_v10`),
`0003_observability` (поля трассировки и `workflow_jobs.duration_ms`). Обе идемпотентны.

JSON-поля хранятся текстом и декодируются единым `db.dec()`. Составные ключи — `db.upsert(..., key=(...))`.
Файлы отчётов — `var/files/<research_id>/`, кэш HTTP — `var/cache/`, секреты — `var/secrets.enc`.

## 8. Интерфейс

Один HTML-каркас и 5 скриптов без сборки и внешних CDN: `charts.js` (SVG-инфографика,
включая `network()` — граф связей документов), `screens_core.js` (UI-01…09, 18…20),
`screens_registry.js` (UI-10…17, 21…26), `screens_v11.js` (UI-27…30: реестр методик,
независимость доказательств, воспроизводимость и сравнение версий, дедупликация и граф),
`app.js` (API-клиент, hash-роутер, меню M01–M32, таблицы, состояния, SSE, тосты, контекст,
статусбар).

Клиент **не пересчитывает** научные показатели. Все числа приходят из API вместе с версией
методики; графики раскрывают исходные данные и выгружаются в CSV.

## 9. Наблюдаемость и трассировка

`isheika/telemetry.py` — контекст `request_id` / `correlation_id` (contextvars). HTTP-слой
оборачивает каждый запрос в `telemetry.scope()`, принимая внешние заголовки
`X-Request-ID` / `X-Correlation-ID` только в безопасном формате и пробрасывая их обратно.
События (`workflow_events`), аудит (`audit_log`) и вызовы внешних API (`audit_api_calls`)
получают метки трассировки; фоновый поток исследования наследует `correlation_id`
инициировавшего запроса. Этапы пишут `duration_ms`.

Чтение: `GET /api/v1/trace/{correlation_id}` (события + этапы + вызовы + аудит), UI-24
(переход по идентификатору из таблицы событий), `GET /metrics` (Prometheus 0.0.4).

## 10. Единый файл запуска

`tools/build_exe.py`: 7zSD.sfx + конфигурационный блок + 7z-архив (встроенный CPython 3.11
x64 + `app/`). Результат — `release/ISHEIKA-NTR-AI.exe`, данные в
`%LOCALAPPDATA%\IsheikaNTR-AI`. Проверки: структура файла, запуск образа под wine64,
прогон приёмочных тестов внутри образа.

## 11. Промышленный контур

```bash
pip install -r requirements-optional.txt
uvicorn isheika.api.adapters_fastapi:app --host 0.0.0.0 --port 8000
```

Тот же сервисный слой и те же маршруты; TLS, OIDC, PostgreSQL, OpenSearch и очередь заданий
подключаются по `ROADMAP.md` без изменения домена.
